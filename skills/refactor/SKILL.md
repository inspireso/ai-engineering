# Test-First Refactoring

## Overview

强制执行测试先行的重构流程，防止"改完才发现坏了"的回滚循环。

**核心原则：重构 = 改变代码结构，不改变外部行为。**

- 没有覆盖当前行为的测试，不准动生产代码
- 每次只做一个小改动，改完立即验证
- 测试红了立刻回滚那一步，不要在红的基础上继续改

## When to Use

触发场景：

- 用户说"重构 X"、"简化 Y"、"把 Z 用更好的方式重写"
- 替换库或框架（如 Apache HttpClient → JDK HttpClient）
- 消除重复代码、抽取公共逻辑
- 用框架特性替代手写实现（如 `@Cacheable` 替代手写缓存）
- 拆分过大的类/函数

何时**不**使用：

- 修复 bug → 用 **superpowers:systematic-debugging**
- 新增功能 → 用 **superpowers:test-driven-development**
- 改变 API 或外部行为 — 那不是重构，是重新设计，停下问用户

## Quick Reference

| 场景 | 动作 |
|------|------|
| 无测试覆盖 | **先停下**，写测试，确认全绿，再重构 |
| 测试在重构前已失败 | 先修测试或修代码让其通过，再开始重构 |
| 一次改动让多个测试红 | 改动太大，回滚，拆成更小的步骤 |
| 想"顺手"清理无关代码 | 不要。开新 commit 或新任务 |
| 想改进 API/签名 | 不是重构。停下，和用户确认 |
| 重构暴露了 bug | 记录下来，重构完成后单独修 |
| 用户要求的"更好方式"会改变行为 | 停下。告知用户差异，由用户决定是否继续 |
| 时间不够写测试 | 缩小重构范围（只做最安全的改动），或建议推迟。绝不跳过测试 |

## Workflow

### 步骤 1：分析现有行为

读取目标文件，列出：

- 所有公开方法/函数签名
- 关键分支和边界条件
- 调用方依赖的副作用（异常、日志、缓存写入等）

### 步骤 2：编写覆盖当前行为的测试

在修改任何生产代码**之前**：

- 为每个公开方法/函数写测试
- 覆盖关键分支、边界值、异常路径
- 测试必须**在当前代码上全部通过** — 这证明测试正确捕获了行为
- 已有测试要审查覆盖率，补充缺失场景

**验证：运行测试，确认全绿。这一步是重构的安全网。**

### 步骤 3：执行重构（小步快跑）

每次只做一个小改动：

1. 做一处改动
2. 立即运行测试
3. 全绿 → 提交或继续下一步
4. 红了 → **立即回滚该改动**，换一种方式重试
5. 同一改动连续失败 3 次 → 跳过，先做其他改动

**禁止：在测试红的状态下继续叠加改动。**

### 步骤 4：验证

- 运行完整测试套件
- 运行 linter / 类型检查（如有）
- 如果重构有意改变了某些行为，更新对应测试并在 commit 说明

### 步骤 5：提交

conventional commit 格式：

```
refactor(<scope>): 简要描述变更和原因
```

## Common Mistakes

### 借口对照表

| 借口 | 实际情况 |
|------|----------|
| "改动很简单，不用写测试" | 简单改动也会坏。写测试 30 秒，调试 30 分钟 |
| "我已经手动测过了" | 手动测试不可重复、不可回归。不算数 |
| "测试写完再重构太慢" | 没测试网的重构出问题后回滚和定位更慢 |
| "顺手把这块也清理了" | 改动范围扩大 = 出问题时定位变难。拆成多次 |
| "测试红了但我知道为什么，继续改" | 不准。立即回滚，红色基础上的改动无法验证 |
| "这是死代码，可以删" | 你的修改没让它变死的话，不要删。提醒用户即可 |
| "顺便把签名改一下更好" | 那是 API 重新设计，不是重构。停下问用户 |
| "用户让我用 X 库替代，那就直接替代" | 先确认 X 库是否能 1:1 保留原行为。不能就停下问用户 |
| "时间不够，只能省掉测试这一步" | 缩范围，不省测试。或告知用户撑不到窗口 |

### 红旗清单 — 看到立刻停

- 还没写测试就开始修改生产代码
- 测试套件不能稳定全绿就开始重构
- 一次提交里同时有"重构"和"修 bug"或"加功能"
- 改了 200 行后才第一次运行测试
- 测试红着继续叠加改动
- "我把签名改一下应该没人用" — 没搜全调用方
- 用户提议的方案（库/特性）无法 1:1 保留原行为，但你打算"差不多就行"
- 时间窗口不够完成"测试 + 小步重构"，但你打算砍掉测试硬上

**任一信号出现：停下，回到步骤 2 或与用户确认。**

## Examples

### 示例提示词

```
重构 AuthConfigCacheService，目标：用 Spring @Cacheable 替代手写缓存逻辑。
先写测试覆盖当前缓存行为（命中、未命中、过期、并发），全绿后再重构。
```

```
简化 OrderProcessor.process() 方法（当前 320 行），拆分职责，行为不变。
```
