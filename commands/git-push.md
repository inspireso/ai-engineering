# Git Push Command

执行推送流程（意图级约束——描述目标与约束，AI agent 可根据项目上下文自行选择最佳执行方式）：

1. 检查工作区状态：存在未提交变更时提示先提交（遵循 `git-commit` 规范）；确认待推送内容为当前分支领先远程追踪分支的 commits
2. 合并远程分支到本地：拉取远程追踪分支的最新变更并合并到当前分支，确保推送可快进、不丢远程提交；若合并产生冲突，尝试分析并解决，解决后继续流程；若冲突过于复杂无法可靠解决，停止并提示用户手动处理
3. 执行代码审查：审查待推送 commits 的 diff（可参照 `/review` 流程），检查是否符合项目规范、安全护栏（硬编码密钥、危险操作）、测试覆盖；若发现问题，修复并重新提交后再进入下一步
4. 展示待推送内容（当前分支、远程追踪分支、领先的 commit 摘要），**推送前必须获得用户明确确认**；用户拒绝则停止
5. 用户确认后执行推送（当前分支到远程追踪分支）；推送失败则展示错误信息并停止
6. 推送成功后核实本地与远程已同步（无领先 commits）

## 使用

```
/git-push
```

## 安全护栏

- **推送前必须用户确认**：未获明确确认不得推送
- 未经用户明确请求，绝不使用 `--force` 类强制推送
- 绝不向 main/master 强制推送
- 未完成代码审查的变更不得推送；review 产生修改时，先提交再推送
